the research question

What counts as "read"

This is the whole question. Everything else — the panel, the risk ranking, the git hook — only makes the answer visible, and if the answer is wrong they are a lie with a progress bar on it. So the model is kept small enough to argue with: a handful of observable signals, weights, and one threshold.

signalobservedpts
visibleon screen for 300 ms or more+1
focusedin the active editor, window focused, 800 ms or more+1
dwellthe viewport held still for a second or more+1
caretyou put the cursor on it, or selected it+1
editedyou typed it yourself+2

The default of 3 points is not an arbitrary pick. It is the smallest value at which the three propositions below are all true at once, and those three are pinned as tests — if a later change to the model breaks one of them, that is not tuning, it is a different product.

What is not counted matters more than the weights. Nothing accrues while the window is unfocused, so a file left in a background tab all day earns one point; scrolling faster than a human reads (45 lines/sec) earns no visibility at all; and any tick longer than two seconds is thrown away whole — the only thing that stops a closed laptop from recording hours of careful reading.

why a percentage alone is useless

Not every unread line is the same event

Forty unread lines of README and three unread lines of auth/session.ts are not the same thing to have missed. So every line is ranked by its path (auth/, billing/, migrations/) and by its content (eval(, process.env, SQL built by string concatenation), and the report is sorted by risk, not by volume.

the composite

Review Score

Coverage is weighted by what it was coverage of. A diff can be well read overall and barely read where being wrong costs the most, and the score says so instead of averaging the difference away.

A component with nothing to measure is not scored zero — it is dropped, and its weight is redistributed over the rest. A diff that never touched critical code should not be penalised for "critical 0%".

In a diff of nothing but added lines, New code and Coverage come out the same. They diverge once existing lines are modified.

where the numbers come from

The scoring model lives in src/core/ and does not depend on the editor: the definition of "read" has to be re-tunable and replayable without VS Code, or there is no way to check it. Nothing is uploaded and nothing leaves the machine — the evidence stays in the git directory of the repository it is about.
